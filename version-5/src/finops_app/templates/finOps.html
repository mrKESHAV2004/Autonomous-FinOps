The data continuum

From raw telemetry to financial strategy. We utilize AWS “Data Exports” for server-side conversion, ensuring strict schema enforcement before machine learning ingestion.

Processing mode
Strict Compatibility (No x_ columns)

  1. Native Export

    Server-side conversion engine. Maps legacy lineItem/UnblendedCost to FOCUS BilledCost, enforcing schema with no x_ columns for strict compatibility.

  2. FOCUS Schema

    Strict nullability constraints. Enforces categorical stability on RegionId and ServiceCategory.

  3. Feature Engine

    Applies np.log1p normalization and Z-Score scaling. Computes CostUsageInteraction terms.

  4. On-Demand ML

    Retrains Isolation Forest & LSTM per session to prevent Concept Drift and ensure context specificity.

  5. Open Source Fallback

    Uses focus-converter for historical CUR to FOCUS transformation via YAML rules.

The data foundation: FOCUS modernization

FOCUS resolves interoperability by mandating vendor-agnostic schemas, enabling ML generalization across CSPs. As detailed in Section 2.1.1.

Structural advantages

  1. 1. Dimensional Uniformity: Fixed schema reduces curse of dimensionality.
  2. 2. Metric Clarity: EffectiveCost for smoothed forecasting vs. BilledCost variance.
  3. 3. Strict Nullability: Minimizes imputation overhead.

Transformation mechanism

From AWS CUR to FOCUS via server-side exports or focus-converter tool for historical data.

The algorithmic engine

Financial time-series data is notoriously non-stationary. Our architecture utilizes a dual-engine approach, leveraging Huber Loss to remain resilient against billing shocks (like RI purchases) that typically derail standard MSE regressions.

  • Isolation Forest (Anomaly)

    Unsupervised detection of “Zombie Resources”.

    • n_estimators=200
    • Interaction Terms

  • Sequential LSTM (Forecast)

    Deep learning for time-series extrapolation.

    • 64 Units
    • Dropout
    • 32 Units
    • Huber Loss

  • DataPreprocessor (Section 3.1)

    Feature engineering for power-law distributions and seasonality.

    • np.log1p
    • Z-Score Scaling
